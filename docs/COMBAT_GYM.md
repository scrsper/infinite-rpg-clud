# Combat Gym

Run `Play Torn Veil Combat Gym.cmd` in this checkout. It serves the existing Babylon client at `http://127.0.0.1:7505/?gym=1&autoplay=1&view=orbit` using the same PlayerController, camera, prediction, BridgeSession and canonical Simulation as the town workbench. The launcher is loopback only. No installation is needed when this checkout's existing dependencies and generated `web/public/models` are present. Use `-Build` after changing client source.

The top-left selector switches between **Combat Gym** and a **disposable Town reference world**. Both stay in separate in-memory World/Simulation instances. Leaving one pauses it and releases input. Returning retains its entities, position and belongings. Neither instance loads or writes an existing town save. Closing the server discards both. This is a testing launcher, not a replacement for the normal persistent-town launcher.

Gym fixtures are authored in `src/sim/world/combatGym.ts` before publication. The default seed is 918271; enter a nonnegative integer up to 2147483647 and select Reset seed to reconstruct the entire gym, including health, people, items, containers and grid. Reset is unavailable in Town. Simulation pause/resume uses the existing workbench control. Partner AI controls only the three single/group partners through the canonical external-controller boundary; it uses ordinary NPC cognition when enabled. The human practice dummy and guide remain passive fixtures. NPC reactions, perceptions, relationships and combat consequences still apply.

Zones: movement/dodge lane; single partner; two nearby group partners; passive human practice dummy; friendly guide, real chest, loose bread/stick and physical furniture. WASD move, Shift sprint, Space dodge, H/LMB strike, G heavy strike, B/RMB guard, F target, T next target, E interact, Esc menu. These are default bindings; the ordinary Settings screen remains authoritative if rebound.

The stage floor and labels are visual overlays on the canonical flat stone grid. Boundary walls and furnishings also exist in the canonical grid. Chest and item actions use the normal interaction system. Static furniture cannot currently be smashed; pottery, debris, weapons/shields and reference-style floating damage/combo UI are not added. No visual damage is substituted for canonical damage. Existing animation limitations are unchanged. This branch uses the latest integrated client at 605022b; the separate TRELLIS motion preview adapter was inspected but not merged into the runtime.

Verification: `npm run typecheck`, `npm run web:build`, `npm exec -- vitest run tests/combat-gym.test.ts tests/web-boundary.test.ts tests/web-input.test.ts`, and `node scripts/web/gym-verify.mjs`. The browser harness uses ordinary keyboard movement, strikes, dodge, dialogue and object interaction. Read-only canonical inspection supplies actual health/events and fixture digests. It checks pause, reset, interrupted input and repeated town/gym switching. It is automation evidence, not a human playtest.

Evidence lives in `.debug/combat-gym`: screenshots, short canvas gameplay recording and `browser-report.json`. The reference URL was blocked locally and Library still materialization failed on Windows; visual design used the parent's actual-video observations. Exact reference-layout fidelity is not claimed.
